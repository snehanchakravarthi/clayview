# Eval run, cloud, 2026-11-03

First run of `tools/eval/eval.py` in a Claude Code cloud session, checking whether the
environment can fetch clips and models and how fast it is. Code is as on
`claude/elastic-blackburn-3a89b2` (5c872ec), unchanged.

**Outcome.** Only comma2k19 ran, and it scored as it does locally (speed ratio 0.95). It took
about **27 min of CPU time for one 60 s clip**, 22 min of it in the street model, which is over
the 20 min per-clip stop threshold, so the rest of the set wasn't run. The other clips can't be
fetched anyway: Wikimedia answers 429 Too Many Requests to this cloud's egress addresses.
The first attempt, before the network policy was widened, is kept below.

## Second attempt, after widening the network policy

Allowed domains added: `upload.wikimedia.org`, `huggingface.co`, `*.hf.co` (Hugging Face
redirects downloads to `us.aws.cdn.hf.co`).

- Models: car-view weights (192 MB) and Mask2Former (827 MB) downloaded in under 2 min.
  The transformers load report lists `swin.layernorm` as MISSING and `relative_position_index`
  as UNEXPECTED; both are harmless (the index is a rebuilt buffer, and Mask2Former reads the
  backbone's stage outputs, not its final layernorm).
- Clips: upload.wikimedia.org answers **429 Too Many Requests** (`retry-after: 600`, Varnish,
  "please contact noc@wikimedia.org"). Still 429 after 10 min and again after 40 min. The session sent only a
  handful of requests and the client IP Wikimedia reported changed between them
  (160.79.106.130, .135), so the limit is on the cloud's shared egress addresses, not this run.

Time per stage on 4 vCPU, from the cache files' timestamps:

| stage | time |
|---|---|
| YOLO11n + ByteTrack (first attempt, cached) | ~2.5 min |
| car views (`orient.py`) | ~2.7 min |
| street model (`segment.py`, Mask2Former Swin-L) | ~22 min |
| **total for a fresh 60 s clip** | **~27 min** |

That's about 11x the Apple GPU's 2.5 min per clip. The whole set, 22 clips, would take about
10 hours in one session like this. The street model is the cost; a run with `--no-world` would
take about 5 min per clip, but it isn't the default pipeline and doesn't score the street.

# First attempt, before widening the network policy


## Environment

- CPU: 4 vCPU, Intel Xeon @ 2.10GHz. RAM: 15 GB, no swap. Disk: about 30 GB free.
- GPU: none (`nvidia-smi` not present; torch 2.15.0+cu132 reports `cuda.is_available() == False`).
  Device "auto" picked **cpu**.
- Python 3.12.3 (via `uv`), uv 0.11.32, system ffmpeg. `uv sync` worked from PyPI;
  `uv run pytest`: 115 passed in 4.4 s.

### Hosts

| host | used for | result |
|---|---|---|
| raw.githubusercontent.com | comma2k19 clip and truth logs | allowed |
| github.com (release assets) | `yolo11n.pt` | allowed |
| pypi.org, files.pythonhosted.org | `uv sync` | allowed |
| **upload.wikimedia.org** | every clip except comma2k19 | **blocked**: proxy answers 403 to CONNECT |
| **huggingface.co** | car-view weights (`orient.py`), Mask2Former street model (`segment.py`) | **blocked**: proxy answers 403 to CONNECT |

`commons.wikimedia.org` is blocked too. To unblock, add `upload.wikimedia.org` and
`huggingface.co` to the environment's allowed domains (Hugging Face may also redirect to
`cdn-lfs.huggingface.co` or `*.xethub.hf.co`, which are also blocked now). Network access
settings are documented at
https://code.claude.com/docs/en/cloud-environments#network-access.

### Speed

- comma2k19 (60 s, 1200 frames at 20 fps, 1164x874): the YOLO11n + ByteTrack pass took
  about **2.5 min on CPU**, so about 8 frames/s. The whole harness call, including the
  failure, took 2 min 43 s of wall time.
- The car-view and street models never ran, so their CPU cost is unknown. Mask2Former on
  4 CPU cores will probably cost more than detection does.
- The Wikimedia clips run at 25 to 60 fps, so expect the detection pass alone to take
  roughly 3 to 8 min per 60 s clip on this hardware.
